# Content Analyzer

**Live app:** https://social-media-content-analyzer-p37j.onrender.com

A web app that takes a PDF or a screenshot of a social media draft, extracts the text, and returns an editorial-style breakdown of how it'll perform: an engagement score, tone, readability, concrete strengths and fixes, a rewritten version, alternative hooks, CTA suggestions, and hashtags.

Upload → Extracting → Extracted text preview → Analyze → Editorial notes.

## Features

- **Upload** — drag-and-drop or file picker, for PDF, PNG, JPG, JPEG, WEBP, BMP, and TIFF (up to 15 MB), with inline validation for unsupported types and oversized files.
- **Text extraction**
  - PDFs are read via their embedded text layer, preserving line/paragraph structure.
  - If a PDF has no usable text layer (i.e. it's a scan saved as a PDF), each page is rasterized and run through OCR automatically — no separate "is this scanned?" step for the user.
  - Images are run through OCR directly, with light preprocessing (grayscale, upscaling small images) to improve accuracy.
- **Analysis**, generated from the actual text — not canned copy:
  - Engagement score (0–100) built from hook strength, length, readability, presence of a CTA, hashtags, emoji, and scannability.
  - Tone/sentiment label.
  - Readability (Flesch Reading Ease + plain-language label).
  - Strengths and improvement points, each only included if it's actually true of the text.
  - A rewritten version — a genuinely different post per input, not a template. It keeps an already-strong opening line intact rather than overwriting it, and only reflows or adds what's actually missing (hook, CTA, hashtags, emoji).
  - Three alternative hooks, 2–3 CTA suggestions, and hashtags pulled from the post's real keywords.
  - If `ANTHROPIC_API_KEY` is set, analysis is generated by the Claude API instead, using the same output shape; if that call fails for any reason, the app falls back to the rule-based engine automatically rather than erroring out.
- **UX** — loading states for both extraction and analysis, empty/error states with specific messages, responsive layout down to mobile, visible keyboard focus, and `prefers-reduced-motion` support.

## Tech stack

- **Backend:** Python, Flask
- **PDF parsing:** [pdfplumber](https://github.com/jsvine/pdfplumber) (text layer), [pypdfium2](https://github.com/pypdfium2-team/pypdfium2) (rasterizing scanned pages for OCR)
- **OCR:** [Tesseract](https://github.com/tesseract-ocr/tesseract) via [pytesseract](https://github.com/madmaze/pytesseract)
- **Images:** Pillow
- **Frontend:** vanilla HTML/CSS/JS — no framework or build step, kept deliberately minimal
- **Optional AI analysis:** Claude API via `requests` (no SDK dependency)

No frontend build tooling is used on purpose — the brief asked to keep dependencies minimal, and a single-page vanilla app covers everything the UI needs.

## Architecture / approach

```
templates/index.html   Single-page frontend shell
static/css/styles.css  Design system + layout
static/js/app.js       Upload → extract → analyze flow, all fetch()-based

app.py                 Flask routes: /, /api/extract, /api/analyze, /api/health
analyzer/extraction.py PDF text-layer extraction + OCR fallback + image OCR
analyzer/analysis.py   Heuristic scoring/rewrite engine + optional AI path
```

The frontend never talks to Tesseract, pdfplumber, or the Claude API directly — everything goes through the two `/api/*` endpoints, which return a consistent JSON shape regardless of which extraction method or analysis engine ran underneath. That means adding a new file type or swapping the analysis engine doesn't require any frontend changes.

### How PDF extraction works

1. Try `pdfplumber` on the embedded text layer.
2. If the average extracted characters per page is below a threshold (i.e. there's effectively no text — a common signature of a scanned PDF), fall back automatically: rasterize each page with `pypdfium2` at ~180 DPI and OCR it with Tesseract.
3. Either way, the response tells the frontend which method was used, and OCR fallback results include a warning so the user knows to double check for scanning artifacts.

### How OCR works

Images are converted to grayscale, auto-oriented (respecting EXIF), and upscaled if small (Tesseract's accuracy drops noticeably below ~1000px), then passed to `pytesseract.image_to_string`. The same pipeline (minus the PDF-specific steps) is reused for OCR'd PDF pages.

### How the analysis works

By default, a rule-based engine reads the actual text: sentence/syllable counts feed a Flesch readability score, punctuation and a small lexicon drive tone detection, regex patterns detect existing hooks/CTAs/hashtags/emoji, and keyword frequency (with repeated words weighted over one-off mentions) drives both the hashtag suggestions and the hook templates. The engagement score is a weighted sum of all of these. The rewrite is built from the same signals — it keeps an already-strong hook rather than overwriting it, and only appends what's genuinely missing.

If `ANTHROPIC_API_KEY` is set, the same request is instead sent to the Claude API with a prompt asking for the identical JSON shape, so the frontend renders either path the same way.

## Setup and installation

**Requirements:** Python 3.10+, Tesseract OCR installed on the system (`apt install tesseract-ocr` on Debian/Ubuntu, `brew install tesseract` on macOS).

```bash
git clone <this-repo-url>
cd content-analyzer

python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env            # optional — only needed for AI-backed analysis

python3 app.py                  # serves on http://localhost:5000
```

### Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | No | If set, analysis is generated by the Claude API. Omit it to run entirely offline on the built-in engine. |
| `ANALYSIS_MODEL` | No | Overrides the Claude model used for AI-backed analysis (default: `claude-sonnet-5`). |
| `PORT` | No | Port for the Flask dev server (default: `5000`). |

## Running tests

```bash
python3 -m unittest discover -s tests -v
```

The suite (20 tests) generates its own PDF/image fixtures on the fly (via `reportlab`/`Pillow`/`img2pdf`) and covers: text-layer PDF extraction, OCR fallback for scanned PDFs, direct image OCR, error handling for unsupported/corrupted/empty files, the analysis engine's scoring and rewrite logic, and all three Flask endpoints.

## Deployment

The app is a standard Flask app and can be deployed anywhere that runs Python + Tesseract (Render, Railway, Fly.io, a VPS, etc.). For production, run it behind a WSGI server rather than the Flask dev server, e.g.:

```bash
pip install gunicorn
gunicorn -w 2 -b 0.0.0.0:$PORT app:app
```

Make sure the host has the `tesseract-ocr` system package installed — it's a native binary, not a Python package, so it won't come from `requirements.txt`.
